# ZGCLab 数据展示系统（本地模拟）

`/home/ubuntu/zgclab-1-web` —— 需求 1 的「数据展示系统」演示页面。
纯静态 HTML/CSS/JS，无外部依赖、无框架、可离线运行，数据来自真实交付快照。

## 展示什么

**20 个验证单位 × 3 个采集角度**，对应任务一的三张目标表：

| 角度 | 目标表 | 记录数 | 字段数 |
| --- | --- | ---: | ---: |
| 新闻舆情 | `t_kt_public_sentiment` | 3,675 | 16 |
| 机构官网 → 线索 | `t_kt_risk_clue_detect` | 1,468 | 35 |
| 社交媒体 | `t_kt_social_media_content` | 1,846 | 34 |

合计 **6,989 条**已审核入表记录，覆盖全部 20 个机构。

### 页面

- **数据总览**：KPI、角度分布、机构排行、月度趋势、平台/风险/标签分布、最新入库
- **机构库**：20 个机构卡片（各角度条数），点击进入机构详情
- **机构详情**：三个角度 Tab + 记录检索 + 分页，点记录看详情
- **数据浏览**：按角度 / 机构 / 关键词 / 标签（风险、平台）筛选，表格分页
- **任务与交付**：数据链路、三张目标表说明、20 单位全表

## 运行

```bash
cd /home/ubuntu/zgclab-1-web
python3 -m http.server 8787 --bind 127.0.0.1
```

打开 <http://127.0.0.1:8787/>。
（服务器上已用 tmux 会话 `zgclab-1-web` 常驻；Mac 端可用
`ssh -L 8787:127.0.0.1:8787 social` 转发后访问。）

## 数据快照

`data/` 下的 `meta.js`、`news.js`、`clue.js`、`social.js` 由 `build_data.py` 生成，
前端按角度懒加载，首屏只读 `meta.js`（十几 KB）。

重新生成（数据源：需求1交付包 `20261011-current-reviewed`）：

```bash
python3 build_data.py
# 或指定其他交付包目录
python3 build_data.py /path/to/delivery-package
```

快照说明：
- 交付表的主键 / 创建时间等系统字段按约定留空，快照内重新生成 `news-1` 这类稳定 ID；
- 正文/翻译按展示需要截断（舆情正文 500 字、线索中文翻译 500 字、社媒原文 1000 字），原文链接保留；
- 只保留交付包内的 20 个机构，历史全量数据不进入本页面。


## 口径说明

- 数据来自需求 1 已审核入表的交付快照，不是编造样例；
- 20 家名单仅用于本阶段练习、回归与验证，不代表历史全量；
- 系统字段（主键、创建/修改时间、删除标记等）由接收系统生成，不计入采集方未完成；
- 无法确认的字段留空，不写「未知」「无」等占位词。
